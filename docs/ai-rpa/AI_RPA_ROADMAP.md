# DDUK ERP AI/RPA 로드맵

## 목적

- 현재 프로젝트에서 AI/RPA가 어디까지 구현됐고, 다음에 무엇을 붙일지 정리한다.
- 구현된 것과 미구현 범위를 섞지 않는다.
- 운영 문서가 아니라 개발/확장 기준 문서다.

## 현재 구현 요약

### 완료된 범위

- 공통 RPA 트리거/콜백/이력 적재
- 구매/발주 공개 가격 수집 카드
- 재고 부족 조회형 카드
- 인사/급여 기준정보 조회형 카드
- 최근 실행 이력/재시도 UX
- 규칙 기반 이상 탐지
- 통계 기반 추천 발주

### 현재 제약

- 회계 RPA는 제외 상태
- 구매 RPA는 공개 페이지 수집만 다룬다
- 회원 전용/세션 기반 데이터는 다루지 않는다
- AI/RPA 실행 더미는 제거되어 실제 실행 결과만 본다
- Phase 4 조회형 챗봇은 본격 구현 완료 상태가 아니다

## 현재 구조 원칙

### 1. AI/RPA는 보조 기능이다

- 기존 ERP CRUD를 대체하지 않는다.
- 수집, 비교, 감지, 추천, 조회 보조에 먼저 집중한다.

### 2. 공통 기반과 시나리오를 분리한다

- 공통 기반:
  - trigger API
  - callback
  - task history
  - 결과 카드 helper
- 시나리오:
  - 구매
  - 재고
  - 인사
  - 이상 탐지
  - 추천 발주

### 3. 더미가 아니라 실실행 결과를 기준으로 본다

- 현재 AI/RPA 시연용 정적 seed 결과는 제거된 상태다.
- 운영 화면은 실제 task history와 실제 결과 파일 기준으로 확인한다.

## 단계별 상태

| 단계 | 내용 | 현재 상태 | 메모 |
| --- | --- | --- | --- |
| Stage 1 | 공통 RPA 흐름 | 완료 | 트리거, 콜백, task history 연동 |
| Stage 2 | 구매/발주 수집 | 완료 | 공개 아망티 페이지 기준 |
| Stage 3 | 재고 부족 조회 | 완료 | 조회형 경고 카드 |
| Stage 4 | 회계 RPA | 제외 | 현재 범위 밖 |
| Stage 5 | 인사/급여 기준정보 조회 | 완료 | 보조 카드 형태 |
| Stage 6 | 운영 UX 보강 | 완료 | 최근 이력, 상태, 재시도 |
| Phase 2 | 이상 탐지 MVP | 완료 | 규칙 기반 |
| Phase 3 | 추천 발주 MVP | 완료 | 통계 기반 fallback 포함 |
| Phase 4 | 조회형 챗봇 | 미완료 | 향후 단계 |
| Phase 5 | ML 고도화 | 미착수 | 충분한 운영 데이터 필요 |

## 다음 우선순위

### 1. 구매 RPA 수집 품질 안정화

- 카테고리/배송비/옵션 추출 품질 보강
- 중복 URL 제거 강화
- 페이지 구조 변경 대응 selector 정리

### 2. 운영 관측성 보강

- task history 필터 강화
- 실패 원인 요약 고도화
- 결과 파일 참조 경로/보존 정책 정리

### 3. Phase 4 조회형 챗봇 진입

- 우선 RAG보다 ERP 조회형 챗봇으로 시작
- 권한/도메인 제한이 먼저
- 답변 실패 시 fallback 문구 기준 필요

## 권장 차기 작업 순서

1. 구매 RPA 수집 필드 안정화
2. RPA 결과/이력 운영성 보강
3. 조회형 챗봇 최소 기능
4. 추천 발주 설명성 강화
5. 운영 데이터 축적 후 ML 고도화 검토

## 비권장 방향

- 아직 없는 외부 사이트/회원 데이터가 있는 것처럼 문서화
- 더미 결과를 다시 startup seed로 넣는 방식
- 자동 발주/자동 반영을 검증 없이 바로 붙이는 것
- 회계 RPA를 현재 단계 완료처럼 취급하는 것

## 차기 확장 체크포인트

### 구매

- 공개 수집만으로 충분한지
- 로그인형/B2B형 확장 필요가 있는지

### 재고

- 단순 조회형에서 경고 설명 강화가 필요한지

### 인사

- 기준정보 조회 외에 계산/검증 보조로 넓힐지

### AI

- 챗봇을 먼저 붙일지
- 추천 정확도 개선을 먼저 할지

## 최종 판단

- 현재 AI/RPA는 “작동하는 보조 기능” 단계까지는 왔다.
- 다음 단계의 핵심은 새 시나리오를 무리하게 늘리는 게 아니라, 이미 붙은 기능을 더 안정적으로 운영 가능한 상태로 만드는 거다.
- 그래서 현재 기준 차순위는 `구매 수집 안정화 -> 운영성 보강 -> 조회형 챗봇` 순서가 가장 맞다.
