# [초안] 재고관리 모듈 데모/테스트 시드 데이터 스펙서 (Inventory Seed Data Specification)

이 문서는 DDUK ERP 재고관리 모듈 검증 및 차트/대시보드의 풍부한 데이터 표현을 위해 구축할 데모 시드 데이터 스펙서이다.

* **상태**: 초안 (Draft)
* **최종 수정일**: 2026-05-27

---

## 1. 마스터 시드 데이터 구성

### 1.1. 창고 데이터 (`warehouses`)
* **WH-MAIN (본사 메인 창고)**: 본사 직영 물류 허브. 원자재 및 완제품의 대부분을 보관.
* **WH-SUB01 (인천 지사 창고)**: 수도권 물류 공급 기지. 완제품 및 일부 포장 자재 보관.
* **WH-SUB02 (부산 지사 창고)**: 영남권 배송 기지. 완제품 위주 보관.

## 2. 거래 및 이력 시드 데이터 구성

### 2.1. 실시간 재고 시드 (`inventories` - 컬럼 정합성 반영)
* 대시보드에서 안전재고 하회 및 품절 상태를 복합적으로 테스트할 수 있도록 의도적으로 수량을 배정한다.
* 물리 테이블 컬럼인 `current_stock` 및 `allocated_stock`에 직접 매핑한다.
  - **ITM-0001 (원자재 찹쌀가루) / WH-MAIN**: `current_stock` 1,200 / `safety_stock` 500 / `allocated_stock` 50 (정상)
  - **ITM-0002 (팥 앙금) / WH-MAIN**: `current_stock` 150 / `safety_stock` 200 / `allocated_stock` 10 (안전재고 부족 경고 유도)
  - **ITM-0003 (포장용 필름) / WH-SUB01**: `current_stock` 0 / `safety_stock` 50 / `allocated_stock` 0 (품절 상태 유도)
  - **ITM-0004 (정통 찹쌀떡) / WH-MAIN**: `current_stock` 800 / `safety_stock` 100 / `allocated_stock` 0 (정상)

### 2.2. 입출고 거래 원장 시드 (`stock_movements`)
* 대시보드의 "최근 30일 출고량" 및 거래 내역의 풍부함을 나타내기 위해 최소 15건 이상의 다양한 날짜(최근 15일 이내)와 유형의 거래 데이터를 분산 적재한다.
* `movement_type` 확장 적용: `INBOUND`, `OUTBOUND`, `TRANSFER_IN`, `TRANSFER_OUT`, `ADJUSTMENT_IN`, `ADJUSTMENT_OUT`, `RETURN_IN`, `RETURN_OUT`
* 입고 사유: `PURCHASE_RECEIVED` (구매 입고), `MANUAL_ADJUST` (조정 입고).
* 출고 사유: `SALES_SHIPPED` (판매 출고).

### 2.3. 창고 이동 승인 시드 (`warehouse_transfers` 및 `warehouse_transfer_items`)
* 상태 흐름의 각 분기(요청대기, 승인완료, 이동완료, 취소)를 모두 확인할 수 있도록 시드 데이터를 적재한다.
  - **TRF-20260527-0001**: 본사 메인창고 -> 인천 지사창고 / ITM-0004 200개 / `COMPLETED` (이동완료 - 재고 반영됨)
  - **TRF-20260527-0002**: 본사 메인창고 -> 부산 지사창고 / ITM-0001 300개 / `PENDING` (승인대기 - 예약재고 `allocated_stock` 300개 묶임)
  - **TRF-20260527-0003**: 인천 지사창고 -> 부산 지사창고 / ITM-0005 50개 / `CANCELLED` (취소/반려 - 예약 해제됨)

## 3. 테스트 시나리오 및 검증용 데이터 조건
* **이중 재검증 시나리오**: `TRF-20260527-0002` (300개 요청)가 `APPROVED`인 상태에서, 수동 재고 조정(`ADJUSTMENT_OUT`)을 통해 `current_stock`을 200개로 급격히 감산시킨다. 이 상태에서 `complete` 호출 시 가용 재고 잔량 부족으로 예외가 발생하는 시나리오를 유도하여 완전 무결한 데이터 검증을 수행한다.
* **멱등성 검증**: 이미 `COMPLETED` 상태인 `TRF-20260527-0001`에 대해 `complete` API를 재호출하였을 때 추가적인 재고 변동이나 원장 적재 없이 성공 코드를 그대로 반환하는지 자동 테스트 코드를 통해 확인한다.
* **상태 전이 예외 검증**: `CANCELLED` 상태인 `TRF-20260527-0003` 건에 대해 승인(`approve`) 또는 완료(`complete`) 처리를 수행하여 적합한 예외(HTTP 400 및 `INVALID_STATE_TRANSITION`)가 떨어지는지 검증한다.
