# DDUK ERP Error Handling

이 문서는 `docs/CONVENTION.md`의 API 응답/보안 규칙 중 에러 처리 기준만 분리한 문서다.  
공통 API 에러 응답은 이 문서를 기준으로 작성하고, 상세 API 목록은 `docs/common/API_STANDARD.md`를 참고한다.

---

## 1. 기본 응답 구조

성공 응답 예시:

```json
{
  "status": "success",
  "data": {},
  "message": "요청이 완료되었습니다."
}
```

에러 응답 예시:

```json
{
  "status": "error",
  "message": "잘못된 요청입니다.",
  "code": "INVALID_REQUEST"
}
```

---

## 2. HTTP 상태코드 기준

- HTTP 상태코드는 실제 결과와 맞게 반환한다.
- 성공인데 200만 고정하지 않는다.
- 검증 실패는 400 계열을 사용한다.
- 인증 실패는 401을 사용한다.
- 권한 없음은 403을 사용한다.
- 미존재는 404를 사용한다.
- 서버 오류는 500 계열을 사용한다.

---

## 3. 노출 금지 정보

- 프론트가 사용자에게 그대로 노출할 수 없는 내부 예외 메시지는 응답에 담지 않는다.
- 스택 트레이스는 응답에 담지 않는다.
- 내부 경로, SQL, 비밀 설정값을 사용자 메시지에 노출하지 않는다.

---

## 4. 작성 기준

- Controller는 입출력 처리에 집중하고, 비즈니스 검증은 Service 레이어에 둔다.
- 외부 입력은 경계에서 검증한다.
- DB 접근은 파라미터 바인딩이나 안전한 ORM 패턴을 사용한다.
- 인증이 필요한 기능은 인증 여부와 권한 여부를 둘 다 확인한다.
